PRD: Return-It — Unified Returns Pickup Service (Web + Mobile)
1) Context
Problem
Online shoppers frequently initiate returns after purchase, but completing the return is still high-friction because:

Not all retailers/carriers offer pickup, so users must travel to a post office or drop-off point.

Returns often involve multiple retailers + different logistics providers, causing multiple trips to multiple locations.

Users may lack a printer for return labels, adding another blocker.

Delays create slower refunds and more mental load (“I’ll do it later” → missed return windows).

Opportunity
A service that turns “approved return + label” into “pickup scheduled + item sent” from any retailer, with:

Pickup booking across many carriers (or a single pickup network that can drop-off on the user’s behalf)

Optional label printing (or QR/label-less workflows where possible)

Return aggregation across retailers, so users can handle multiple returns in one place

Hypothesis
Users will pay for a service that:

Saves time and travel by enabling doorstep pickup for any return

Reduces friction via email parsing and “returns dashboard”

Speeds up refund initiation by getting parcels into the network faster

Product Principles
Fast to schedule (under 60 seconds from “I have a label” to booked pickup)

Trust & transparency (clear pricing, tracking, proof of handover)

Retailer-agnostic (works with Amazon, Shein, etc.)

Carrier-flexible (supports many carriers; doesn’t rely on any single one)

Unit economics sketch (illustrative, UK urban assumptions)
Below is a simple variable-cost model for Concierge pickup (Mode 2). The biggest driver is pickups per hour (route density).

Assumptions (example)

Driver wage: £15/hour

Loaded overhead (insurance, payroll, ops): +25%

Avg pickups per hour: 3 (can be 2–5 depending on density)

Avg travel per pickup: 2.5 miles

Travel cost: £0.45/mile (fuel + vehicle wear proxy)

Label printing + consumables: £0.50 (paper/ink/tape amortized)

Ops support per order: £0.60 (customer service + tooling)

Failed pickup rate: 8% (no-shows, access issues) rolled into cost

Cost per successful pickup (at ~3 pickups/hour)

Labor: £15 * 1.25 / 3 = £6.25

Travel: 2.5 * 0.45 = £1.13

Print/consumables: £0.50

Ops support: £0.60

Subtotal: £8.48

Adjust for 8% failures: £8.48 / (1–0.08) ≈ £9.21

Now add payment processing (roughly) ~£0.60–£0.70 on a £10–£12 charge, and your all-in variable cost is ~£9.8–£10.0.

What this means
At £11.99 price, gross margin is only about £2 (~17%) at 3 pickups/hour.
To make this attractive, you need either:

higher route density (4–5 pickups/hour), or

higher price / add-ons / bundles, or

mix in cheaper Mode 1 orders, or

partnerships where retailers subsidize.

Sensitivity (why density is everything)
Using the same assumptions above, cost per successful pickup drops fast as density increases:

2 pickups/hour → ~£12.61 cost (hard to profit unless you charge ~£15–£18)

3 pickups/hour → ~£9.21 cost

4 pickups/hour → ~£7.51 cost

5 pickups/hour → ~£6.49 cost

So your product and ops should actively manufacture density:

Offer time windows that encourage batching (“save £2 if you choose Tomorrow 12–4”)

Bundle multiple parcels/returns at one address

Start with dense geographies (Zone 1–3 style rollouts)

Incentivize off-peak
